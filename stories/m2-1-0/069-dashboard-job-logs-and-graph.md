# ST-069 — Stream job logs and progress, and show job relationships

**Milestone:** M2 · **Epic:** m2-1-0 · **Priority:** must · **Depends on:** ST-045, ST-039

## Context

Makes the job page live: while it is open, the job's captured log lines stream in as the handler writes them and can be searched, and its progress bar moves, on the page and in lists (REQ-316). It also draws a job's parent, child and batch relations as a graph with each job's state (REQ-317, should) and, where an application registers one with AddJobLink, links a job to a page of the application's own (REQ-318, may). REQ-318 carries no milestone tag; the planner placed it with the full dashboard that hosting REQ-36 puts in M2.

Builds on ST-045 (captured log lines, REQ-165 and INV-126; progress, REQ-166; masking of `[Sensitive]` values, INV-124), ST-039 (batches, REQ-177, after ST-038's continuations and parent ids), ST-033 (the job detail page, REQ-309, which already lists captured logs, progress, parent and children and which this story keeps holding) and ST-032 (live updates over Server-Sent Events with a polling fallback, REQ-315, TECH-89). Built on by ST-080 (exception chains on the job page, M3) and ST-075 (NFR-16 for these queries).

Lives in Bellhop.Dashboard (TECH-88): the job page and the lists in the React front end (TECH-93), fed through the JSON API (TECH-92) and Server-Sent Events (TECH-89). Lines and progress are read from the store, where the worker node that runs the job wrote them, so a node that only maps the dashboard streams them too (hosting REQ-51). REQ-318 names AddJobLink; where it is registered and its signature are not in the specs (open question 4).

## Acceptance criteria

### AC-1 · REQ-316 · must

> While a job page is open, the system shall stream the job's captured log lines live, let the viewer search them, and show the job's progress bar, which lists also show.

- Given a processing job whose handler writes lines through the job-scoped logger at or above the capture level (stored by REQ-165), and a viewer with its page open, when the handler writes a line, then the line appears on the open page without a reload, over Server-Sent Events and, where they are unavailable, over the polling fallback (REQ-315).
- Given the job runs on a worker node and the page is served by another node that only maps the dashboard, then the lines stream all the same.
- Given a job that has finished, then its page shows every captured line, up to the truncation mark where INV-126 truncated the log.
- Given captured lines, when the viewer searches for a text that some lines contain, then those lines are shown and lines that do not contain it are not.
- Given a line that logs a `[Sensitive]` payload value, then the value is masked in the stream and in search results, and searching for the unmasked value finds nothing (INV-124).
- Given the handler reports progress with a fraction and a message (REQ-166), then the open page's progress bar shows that fraction and message without a reload, and the jobs list (REQ-308) shows the same bar for that job.
- Given the page and its stream are closed, then the dashboard issues no further store queries for them (NFR-11).
- What search matches, and how soon a line must appear, are open questions 1 and 2.

### AC-2 · REQ-317 · should

> The system shall show parent, child and batch relationships as a graph with each job's state.

- Given a job with a parent (a continuation, REQ-170, or a job enqueued by a handler, jobs REQ-154), children, and membership of a batch (REQ-177), when its page is open, then a graph shows the job, its parent, its children and its batch, each job with its current state.
- Given a related job changes state while the page is open, then its state in the graph is updated (REQ-315).
- Given a job page, then the graph shows no job that is not related to it.
- How far the graph reaches and how a large batch is shown is open question 3.

### AC-3 · REQ-318 · may

> Where a job link is registered for a job type with AddJobLink, the system shall show a link from that type's jobs to the URL the application computes from the job.

- Given AddJobLink registered for job type A with a function that computes a URL from the job, when a job of type A is shown, then the page shows a link to the URL computed from that job; two A jobs that compute different URLs link to different places.
- Given a job type with no registration, then its jobs show no such link.
- What the page shows when the function fails or returns no URL, which URLs are accepted, and whether lists show the link too, is open question 4.

## Tests

Every test carries one `Trait("Req", "<id>")` for each item it verifies.

- Unit, Bellhop.Dashboard: REQ-318's link computation per registered type; REQ-317's assembly of a job's relations.
- HTTP and integration, against the dashboard in an in-process test server with a worker host on the same store: REQ-316 over Server-Sent Events and over the polling fallback, search, progress on the job page and in the jobs list, and a dashboard-only node.
- Browser end-to-end: REQ-316's live lines and progress bar, REQ-317's graph with states, REQ-318's link.

- Must keep holding: REQ-309 and INV-124 tests stay green.
- Not automated: whether the graph stays readable for a large batch is reviewed by hand. NFR-48 and NFR-49 for the full dashboard are demonstrated in ST-077.

## Open questions

1. **Decide in delivery** · REQ-316: what does search match (a substring or words, with or without case, the message only or the structured properties too), and does it run over every captured line of the job in the store or only over the lines loaded on the page? NFR-16 pages every list.
2. **Decide in delivery** · REQ-316: how soon after a line is stored, or progress is reported, must the open page show it for it to count as live? REQ-315 and TECH-89 set the transport but no delay, and a test needs a bound.
3. **Decide in delivery** · REQ-317: how far does the graph reach (direct parent and children, the whole chain, continuations of continuations, every member of the batch), and how is a batch with thousands of members shown? No limit is given.
4. **Decide in delivery** · REQ-318: where is AddJobLink registered (the AddBellhop builder or dashboard options), what are its signature and the link's text, what does the page show when the application's function throws or returns nothing, and is any URL scheme accepted? It is public API under NFR-20, and the computed URL is rendered into the page.
