# ST-087 — Expose the dashboard API to MCP clients

**Milestone:** M3 · **Epic:** m3-1-x · **Priority:** may · **Depends on:** ST-066, ST-065, ST-077

## Context

Ships Bellhop.Mcp, a Model Context Protocol server over the dashboard JSON API with list, inspect, requeue, trigger and pause tools, so assistants and other MCP clients can read and operate Bellhop with the same permissions and API keys as the dashboard (TECH-121). INV-301 already covers MCP reads and operate actions, and the anonymous permissions apply to MCP as to the pages (the dashboard glossary's anonymousPermission).

Builds on ST-031 (the JSON API, TECH-92, and the permission rules INV-300, INV-301 and INV-302), ST-034 (the operate actions behind requeue, trigger and pause), ST-065 (permissions by role or claim, REQ-306) and ST-066 (API keys: REQ-305, INV-307, INV-308), and comes after the accepted 1.0 (ST-077). Only ST-090 builds on it.

Lives in the Bellhop.Mcp package (TECH-121, TECH-124). How the server is hosted and reached, the tools' names and schemas, and what list and pause apply to are not in the specs (open questions 1 to 3).

## Acceptance criteria

### AC-1 · TECH-121 · may

> **MCP server** — The Bellhop.Mcp package shall implement a Model Context Protocol server over the dashboard JSON API with list, inspect, requeue, trigger and pause tools, using the same permissions and API keys.

- Given an MCP client with a view-scope API key, when it calls list and inspect, then it gets what the JSON API returns for the same reads (TECH-92). When it calls requeue, trigger or pause, then the call is refused, nothing changes (INV-301), and the client sees a tool error.
- Given an operate-scope key, when the client calls requeue on a dead-lettered job, trigger and pause, then each takes the same effect as the same action through the JSON API, under the principal name "apikey:" followed by the key's name (REQ-305).
- Given a revoked, expired, past-expiresAt or unknown key, then every tool call is refused, as the JSON API refuses it with 401 (INV-308), and nothing changes.
- Given a ReadOnly dashboard, then requeue, trigger and pause are refused whatever the key's scope (INV-302).
- Given no authorization requirement in Development, then an anonymous MCP request has operate (REQ-300); given AllowAnonymous() outside Development, it has view only (REQ-342).
- Whatever authenticates an MCP request, its permission is decided as for the JSON API: view for list and inspect, operate for requeue, trigger and pause (INV-301, REQ-306).
- Inspection: Bellhop.Mcp reads and acts only through the dashboard JSON API and references no store package, so it cannot bypass INV-301. The reviewer records the check, the MCP library it uses, its licence and the vulnerability scan (NFR-44) in Notes.

## Out of scope

- The JSON API, permissions and keys: ST-031, ST-065 and ST-066 (TECH-92, INV-301, REQ-306, REQ-305).
- Other operate actions as tools (retry, cancel, delete, edit, launch, limits, key management, acknowledging a store reset): TECH-121 lists five tools. A key-authenticated request can never create or revoke keys anyway (INV-307).
- Arbitrary script execution: hosting REQ-8.
- Third-party dashboard plugins: hosting REQ-6 (extension is through DI hooks and the JSON API only).
