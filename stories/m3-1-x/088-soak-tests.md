## Acceptance criteria

### AC-1 · NFR-3 · must

> **Zero-tuning deployment** — The system shall run a deployment of 3 nodes processing 100 jobs per minute correctly and quietly on default settings.
>
> *Measure:* 24 h soak, 3 nodes, 100 jobs/min, all defaults: 0 lost jobs, 0 duplicates outside the at-least-once window, 0 warnings or errors logged · *Verification:* test
>
> *Notes:* The 24 h duration and the "0 warnings" reading of "quietly" are mine; the source gives only the 3 nodes and 100 jobs/min. Decided by the owner on 2026-11-06: soak and load testing move to a later phase (M3), so this is not verified before 1.0.

- Given 3 nodes with AddWorker() and every Bellhop option at its default on one store, and job handlers that do not fail, when jobs are enqueued at 100 per minute for 24 hours, then every enqueued job ends Succeeded; any that does not counts as lost, and the measure needs 0.
- The test records every start with job id, node and time. A job that starts more than once counts as a duplicate unless the repeat falls within the duplicate window of hosting REQ-10, which equals LeaseDuration (jobs REQ-102); the measure needs 0. How the window is measured is open question 3.
- Given any warning or error logged by any of the 3 nodes during the 24 hours, then the run fails, even if every job succeeded.
- The result, the store, the versions and the run's link are recorded in Notes.
