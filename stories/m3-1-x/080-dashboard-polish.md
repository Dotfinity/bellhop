# ST-080 — Show readable exception chains, branding and localised UI strings

**Milestone:** M3 · **Epic:** m3-1-x · **Priority:** should · **Depends on:** ST-069, ST-077

## Context

Makes failed attempts readable and lets a team make the dashboard its own. The job page shows a failed attempt's exception chain with inner exceptions and AggregateException flattened, async state-machine frames collapsed, the job's own frames highlighted, a copy button and the raw stack trace still at hand (REQ-330). Title, logo, favicon and accent colour come from options, job types show their `[JobName(Display = ...)]` name, and dates appear in the browser's time zone with the server's zone on hover (REQ-331). Every UI string comes from a resource bundle, with English built in and other languages added as JSON bundles (NFR-52).

Builds on ST-033 (the job page and its attempts with exceptions, REQ-309), ST-069 (the job page's live logs and relationships, REQ-316 to REQ-318), ST-002 (the Display property of `[JobName]`, TECH-18) and ST-032 (the shell and its dashboard-wide checks: NFR-42, NFR-47, NFR-50), and comes after the accepted 1.0 (ST-077). It must keep NFR-16 holding: any list it adds or changes stays paged and backed by an index. Only ST-090 builds on it.

Lives in Bellhop.Dashboard (TECH-88): the React front end (TECH-93) with its embedded assets (TECH-91) and the options that feed it. The option names for branding and for adding a language, the JSON bundle format and how the dashboard picks a language are not in the specs (open questions 2 and 4).

## Acceptance criteria

### AC-1 · REQ-330 · should

> When a job page shows a failed attempt, the system shall show the exception chain with inner exceptions and AggregateException flattened, async state-machine frames collapsed, the job's own frames highlighted and a copy button, with the raw stack trace still available.

- Given a failed attempt whose exception has nested inner exceptions, when the job page shows it, then every exception of the chain is shown, inner exceptions included.
- Given an AggregateException in the chain, including one nested in another, then its inner exceptions are shown flattened into the chain rather than as further levels of nesting.
- Given a stack trace with async state-machine frames, then those frames are collapsed in the chain view, and the raw stack trace, uncollapsed, is still available on the same page.
- Given frames from the job's own code and from elsewhere, then the job's own frames are highlighted and the others are not. Which frames count as the job's own, and what the copy button copies, are open question 1.
- Given the chain view, then the copy button works under the strict Content-Security-Policy (NFR-42) and with the keyboard alone (NFR-50).
- Property: over generated exception trees (inner exceptions and AggregateExceptions nested to random depth, frames with and without async state machines), every exception that is not an AggregateException appears in the shown chain, no AggregateException appears as a level of nesting, and the raw stack trace equals the stored one.

### AC-2 · REQ-331 · should

> The system shall show title, logo, favicon and accent colour from options, each job type's display name from [JobName(Display = ...)], and dates in the browser's time zone with the server zone on hover.

- Given a title, logo, favicon and accent colour set in options, when any page is opened, then it shows that title, logo, favicon and accent colour.
- Given a job type registered with `[JobName("...", Display = "...")]` (TECH-18), then the pages that show that job type show its display name. Whether it replaces the job name or sits beside it, and what a type without Display shows, are open question 3.
- Given a date on any page and a browser whose time zone differs from the server's, then the date is shown in the browser's time zone, and hovering it shows the same instant in the server's zone. Which zone is "the server zone" is open question 3.
- Property: over random instants and pairs of time zones, daylight-saving transitions included, the browser-zone text and the server-zone text name the same instant.

### AC-3 · NFR-52 · should

> **Localisation** — The dashboard shall keep every UI string in a resource bundle, with English built in and other languages added as JSON bundles through options or upstream contributions.
>
> *Measure:* 0 hard-coded UI strings · *Verification:* inspection

- Inspection: the reviewer goes through the front-end source and every server-produced text a page shows and finds 0 UI strings outside the resource bundle. A lint rule that flags string literals in the front end may support the review; the reviewer's count is the pass condition, recorded in Notes with the method used.
- Given only the built-in English bundle, then every page shows all its text from that bundle.
- Given a JSON bundle for another language added through options, when the dashboard is shown in that language, then the bundle's strings replace the English ones on every page.
- Given a JSON bundle contributed to the repository, then it ships with Bellhop.Dashboard and is used in the same way as one added through options.
- The bundle format, the option, how the language is chosen and what a key missing from a bundle shows are open question 4.
