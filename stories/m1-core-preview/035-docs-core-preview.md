# ST-035 — Write the getting-started, concepts and recipe docs with compiled snippets

**Milestone:** M1 · **Epic:** m1-core-preview · **Priority:** must · **Depends on:** ST-028, ST-034

## Context

Starts the documentation, kept in the repository and compiled in CI so it cannot drift from the code (NFR-28), with the first pages a new user needs: getting started, matching the §3 five-minute path (NFR-24); concepts, covering at-least-once delivery, leases, misfire, overlap and time zones with the duplicate window (NFR-25); recipes for the plugins Bellhop deliberately does not ship (NFR-29); the two-line Prometheus setup (NFR-36); and the catalogue of EventIds that internal failures are logged with (NFR-51).

Builds on ST-028 (the Bellhop Meter and the standard Prometheus exporter, TECH-98, TECH-99) and ST-034, the last M1 dashboard story, so every M1 feature exists when its page is written; the recipes use ST-010's execution middleware (TECH-28) and ST-003's ISchedule (TECH-25). ST-037 builds on it, and ST-073 keeps NFR-28 holding when it adds the 1.0 pages. NFR-24 is verified here before ST-037 demonstrates NFR-1, because the page follows the §3 path that ST-037 runs; NFR-24's own demonstration, a new user finishing in five minutes, is recorded in ST-037. NFR-51 is owned here because its measure includes the catalogue "published in the docs"; every earlier story has logged with stable EventIds as a standing rule, and this story's inspection checks all of them.

The docs live in the repository (NFR-28); the specs name no docs tool, site or folder. The recipes are samples, not packages (NFR-29): the lock recipes show what TECH-51's notes allow handler code to do. Where the reference §3 snippet is kept now is open question 1.

## Acceptance criteria

### AC-1 · NFR-24 · must

> **Getting-started page** — The documentation shall open with a getting-started page that matches the §3 five-minute path exactly and can be completed in five minutes.
>
> *Measure:* page code identical to §3; a new user completes it in ≤ 5 min · *Verification:* demonstration

- Inspection: the documentation opens with the getting-started page, and its code is identical to the §3 snippet, character for character. Where that snippet is kept is open question 1. The page's code compiles in CI (NFR-28).
- Demonstration, recorded in ST-037: a developer new to Bellhop completes the page in five minutes or less, using only the page.

### AC-2 · NFR-25 · must

> **Concepts page** — The documentation shall include a concepts page covering at-least-once delivery, leases, misfire, overlap and time zones, stating the duplicate window (the lease length) and recommending idempotent handlers and UniqueKey.
>
> *Measure:* each listed concept has a section; the duplicate window is stated with its default value · *Verification:* inspection

- Inspection: the concepts page has a section for each of at-least-once delivery, leases, misfire, overlap and time zones; it states the duplicate window as the lease length with its default, LeaseDuration 60 s (jobs REQ-102); and it recommends idempotent handlers and UniqueKey. The reviewer records the check in Notes.

### AC-3 · NFR-28 · must

> **Verified, versioned docs** — The project shall version the documentation with the code and compile every documentation snippet in CI.
>
> *Measure:* docs live in the repo; CI fails when a snippet does not compile · *Verification:* inspection

- Inspection: the documentation is in the repository and versioned with the code.
- CI compiles every documentation snippet and fails when one does not compile. Checked once with a branch that breaks one snippet, whose CI run must fail; the run is recorded in Notes.
- Whether snippets that are not C# (configuration JSON, the SQL of TECH-47, shell commands) are checked, and how, is open question 4.

### AC-4 · NFR-29 · should

> **Recipe samples** — The documentation shall show, as samples rather than packages, IDistributedLockProvider used from a handler, a [Lock("name")] execution middleware, a MediatR bridge through execution middleware and carbon-aware scheduling through ISchedule.
>
> *Measure:* each recipe present and compiled (NFR-28) · *Verification:* inspection

- Inspection: the documentation has the four recipes, IDistributedLockProvider used from a handler, a [Lock("name")] execution middleware, a MediatR bridge through execution middleware (TECH-28) and carbon-aware scheduling through ISchedule (TECH-25), and each compiles in CI (NFR-28).
- No package is published for any recipe, and no first-party package references a lock library (TECH-51, ST-001's audit).
- Which MediatR version the bridge compiles against is open question 3.

### AC-5 · NFR-36 · must

> **Prometheus setup documentation** — The documentation shall show Prometheus export as a two-line setup.
>
> *Measure:* the documented setup is ≤ 2 lines of application code · *Verification:* inspection

- Inspection: the Prometheus page shows the setup as at most two lines of application code, using the standard OpenTelemetry Prometheus exporter and no Bellhop-specific exporter package (TECH-99), and the snippet compiles in CI (NFR-28).

### AC-6 · NFR-51 · must

> **No swallowed exceptions** — When any internal failure occurs (store, scheduler, serialization or recovery error), the system shall log it through ILogger with a stable EventId and the job id where applicable.
>
> *Measure:* every catch block in the engine logs with a catalogued EventId; catalogue published in the docs · *Verification:* inspection

- Inspection: every catch block in the engine logs the failure through ILogger with an EventId from the catalogue, and with the job id where the failure concerns a job; none swallows the exception. The reviewer records in Notes how the catch blocks were found and the result.
- The catalogue is published in the docs. A test compares the EventIds the code defines with the catalogue and fails on any difference in either direction, so a later story cannot add an EventId without documenting it.
- Which packages count as "the engine", and how EventIds are numbered and named, is open question 2.
