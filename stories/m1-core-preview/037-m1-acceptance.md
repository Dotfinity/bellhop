# ST-037 — Accept M1: run the core preview end to end on real infrastructure

**Milestone:** M1 · **Epic:** m1-core-preview · **Priority:** must · **Depends on:** ST-035, ST-036 · **Kind:** acceptance

## Context

The acceptance run of M1, the core preview of hosting REQ-36. Whoever runs it builds the §3 application on a real PostgreSQL server, runs fire-and-forget, delayed and recurring jobs with retries, dead letters and recovery end to end, watches them on the dashboard, and breaks things on purpose: a node killed mid-job, the store down at startup, a node clock skewed from the database, and several nodes started at the same moment. It owns the two demonstrations M1 makes, minimal setup (NFR-1) and worker services and console hosts (NFR-4), and records the demonstrations that other M1 stories point here: NFR-24 (ST-035), NFR-48 and NFR-49 (ST-032), and NFR-50's manual keyboard pass for the M1 preview release (ST-032).

Builds on ST-035 and ST-036, and through them on every M1 story; nothing builds on it, and ST-077 does the same for M2. A finding where the specs are wrong or silent goes to refiner-requirements first; a finding where the build is wrong becomes a new story with the next free number.

It adds no package or public type. It uses Bellhop, Bellhop.PostgreSql and Bellhop.Dashboard as packaged (TECH-124), at one version with exact-version dependencies between them (TECH-50). Everything is recorded in this story's Notes by whoever runs it: the application code, package and PostgreSQL versions, the steps, what was observed and the findings.

## Acceptance criteria

### AC-1 · NFR-1 · must

> **Minimal setup** — The system shall give a developer a working single-node setup with only AddBellhop(...), a store, AddWorker() and job registration, without creating a schema by hand, choosing polling intervals, writing an authorization filter, configuring a serializer, registering a hosted service or pinning package versions.
>
> *Measure:* the §3 Program.cs (register, pick a store, add the worker, map the dashboard) runs jobs end to end with no other Bellhop code or configuration; the dashboard line is optional · *Verification:* demonstration
>
> *Notes:* Decided by the owner on 2026-11-06: the client and the worker are opt-in (TECH-128); the §3 snippet in requirements.md now includes AddWorker().

- Demonstration: a new project whose Program.cs is the §3 code (where it is kept is open question 1): register with AddBellhop, pick the PostgreSQL store, add the worker, register the jobs, map the dashboard. Against an empty PostgreSQL database it runs a fire-and-forget, a delayed and a recurring job to Succeeded with no other Bellhop code or configuration. No schema was created by hand (AutoMigrate, hosting REQ-21, REQ-22), no polling interval chosen, no authorization filter class written, no serializer configured, no hosted service registered (TECH-11), and no package version pinned by hand: the store and dashboard packages bring the matching Bellhop version (TECH-50).
- The same project with the dashboard line removed still runs the three jobs: the dashboard line is optional.
- Recorded in Notes: the Program.cs used, the package versions, the environment name and the observed run.

### AC-2 · NFR-4 · must

> **Worker services and console hosts** — The system shall support worker services and console hosts as first-class hosts.
>
> *Measure:* every feature except the dashboard works in a Generic Host worker and a console app that reference no ASP.NET Core package · *Verification:* demonstration

- Demonstration: a Generic Host worker service and a console app, each referencing Bellhop and Bellhop.PostgreSql and no ASP.NET Core package (none in the resolved dependency graph, and no ASP.NET Core framework reference), run every M1 feature except the dashboard: enqueue and schedule, recurring jobs, retries and dead letters, lease recovery, traces and metrics (TECH-97, TECH-98) and the health check (TECH-101).
- Recorded in Notes: both dependency graphs and what each app ran.
- Whether the console app builds a Generic Host or runs without one is open question 2.

## Tests
