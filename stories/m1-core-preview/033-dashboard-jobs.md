# ST-033 — Browse jobs on the jobs list and job detail pages

**Milestone:** M1 · **Epic:** m1-core-preview · **Priority:** must · **Depends on:** ST-032

## Context

Adds the two pages an operator uses to find and inspect a job: the jobs list, filterable by state (Unroutable included), name, queue, tag, correlation id and time range (REQ-308), and the job detail page with the payload, state timeline, attempts with their exceptions, interrupted attempts marked, captured logs, progress, parameters, parent and children, and the trace id (REQ-309).

Builds on ST-032 (shell, live updates and the dashboard-wide checks these pages keep: NFR-42, NFR-47, NFR-48, NFR-49, NFR-50) and ST-031 (INV-301). Several of the fields are written by later stories: tags and correlation ids by ST-044, which keeps REQ-308 holding; captured logs and progress by ST-045; parent and children by ST-038 and ST-039. The pages are built against what exists and tested by writing those values into the store directly; ST-045 and ST-069 keep REQ-309 holding. ST-034 continues from these pages, and ST-044 and ST-048 build on them.

Lives in Bellhop.Dashboard (TECH-88) and its JSON API (TECH-92). The tag and correlation-id filters run over IJobIndex (TECH-32), and every store serves every filter (REQ-308's notes); the rest reads IJobStore (TECH-31). How filters combine and match, the list's order and paging, and the answer for an unknown job are not in the specs (open questions 1, 2 and 4).

## Acceptance criteria

### AC-1 · REQ-308 · must

> The system shall show a jobs list filterable by state (including Unroutable), name, queue, tag, correlation id and time range.
>
> *Notes:* Decided by the owner on 2026-11-06: free-text search over payloads is dropped as overkill; tags (BLT-9) are how jobs are found by business key, and every store serves these filters.

- Given jobs in every state, Unroutable included, written into the store, when the list is filtered by one state, then it shows exactly the jobs in that state.
- Given jobs of several names and queues, when the list is filtered by a job's full name, then it shows exactly the jobs with that name; when filtered by a queue, exactly the jobs in that queue.
- Given IJobIndex entries for a tag and for a correlation id added directly (TECH-32; ST-044 writes them later), when the list is filtered by that tag or that correlation id, then it shows exactly the jobs QueryAsync returns for it.
- Given a time range, then a job is shown when the range contains all of its timestamps and not shown when the range contains none of them. Which timestamp the range applies to is open question 1.
- Given a filter that matches no job, then the list is empty, not an error.
- Property, on the in-memory and the PostgreSQL store: for generated job sets and each single filter, the list equals the set computed directly from the store. How several filters combine is open question 1.
- No free-text search over payloads is offered (REQ-308's notes).

### AC-2 · REQ-309 · must

> The system shall show a job detail page with the payload, state timeline, attempts with exceptions, interrupted attempts marked as such, captured logs, progress, parameters, parent and children, and the trace id.

- Given a job written with a payload, a state history, attempts with exceptions, parameters (TECH-30), a trace context (REQ-154), and, written directly, captured logs and progress (ST-045) and a parent and children (ST-038, ST-039), when its detail page is opened, then it shows the payload, every state change of the timeline in order, each attempt with its exception, the captured logs, the progress, the parameters, links to the parent and to each child, and the trace id.
- Given an attempt that ended by lease expiry, recorded with reason Interrupted (jobs REQ-132, REQ-133; SCN-102), then the page marks it as interrupted, distinct from an attempt that failed with an exception. Whether a run released at shutdown (jobs REQ-140, SCN-115) is shown as an interrupted attempt is open question 3.
- Given a job without captured logs, progress, parameters, parent or children, then the page shows the rest without an error.
- Given the page is open, when the job changes state, then the timeline shows the change without a reload (REQ-315).
- What the page and the JSON API answer for a job id that does not exist, was deleted (REQ-144) or was removed by retention (REQ-104) is open question 4.

## Open questions

1. **Decide in delivery** · REQ-308: how several filters combine (all must match, or any), how the name filter matches (exact, prefix or contains; aliases too), and which timestamp the time range applies to (enqueued, last state change, or scheduled time). REQ-308 lists the filters only.
2. **Decide in delivery** · REQ-308, TECH-32: the list's order and paging. IJobIndex's QueryAsync takes a page, and the JSON API's paging becomes a public contract (TECH-92, NFR-20).
3. **Decide in delivery** · REQ-309: is a run released at shutdown (jobs REQ-140; SCN-115 calls it "the run interrupted by shutdown") shown as an interrupted attempt, although its attempt is taken back? Only lease expiry records the reason Interrupted (REQ-132, REQ-133).
4. **Decide in delivery** · REQ-309: what the detail page and its JSON API answer for a job id that does not exist, was deleted (REQ-144) or was removed by retention (REQ-104): status code and message.
